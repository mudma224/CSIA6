## 0. Architecture choice and responsibilities

**Recommended minimal setup:** keep `CSIA6` as one Next.js app with route handlers under `src/app/api/`; add **Supabase PostgreSQL** for durable user/parcel records and **Supabase Auth** for real sessions once a supported login method is configured. DB ownership/policies live in SQL migrations; the server mediates application requests and authorizes operations, while **RLS independently protects data**. The Data Science service is a separate internal FastAPI *only if D1 proves it necessary*. No dedicated CRUD microservice, message broker, storage bucket or queue unless measured needs arise. The scientist owns scoring; backend owns security, validation and mapping; frontend owns input UX/transport/rendering.

**Alternatives to record:** use a plain Postgres + separate session provider instead of Supabase (more self-host maintenance); place CRUD in FastAPI (second app runtime, CORS/JWT duplication), or build an all-in-one Next.js science service (Python-model packaging mismatch). Decide **one** CRUD API owner and deployment topology; no parallel implementations. Supabase SSR cookie-based Auth requires the supported `@supabase/ssr` flow and correctly managed session refresh; choose `proxy.ts` or `middleware.ts` based on **actual Next version**, not historical guides. Public keys are not secrets, service-role keys are and **never go in `NEXT_PUBLIC_*`**.

## 5. Parcel RLS migration — **CONDITIONAL CODE CANDIDATE, NOT APPROVED**

This is an **isolated minimal persistence proposal for the M2 UI form**, **not** the DS model request. Values such as zone/irrigation remain farmer-entered UI descriptors, not agronomic enumerations. Execute only after C03 and corresponding privacy/validation review. In particular, long-term storing of manual coordinates requires an explicit consent/deletion policy; otherwise **remove both coordinate columns from the approved migration**.

Copy to the *actual generated* `supabase/migrations/<timestamp>_create_parcels.sql` **only if the C03 schema and UI review accept every field and constraint**:

```sql
-- PROPOSAL — NOT APPROVED; create only after contract/schema gate.
create extension if not exists pgcrypto;

create table public.parcels (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id) on delete cascade,
  name text,
  zone_ui text not null,
  area_ha numeric(12, 4),
  irrigation_ui text not null,
  lat_user decimal(9, 6),
  lon_user decimal(9, 6),
  recent_crop_note text,
  recent_crop_season_note text,
  earlier_crop_note text,
  earlier_crop_season_note text,
  planned_season_note text,
  planned_season_unknown boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint valid_area check (area_ha is null or area_ha > 0),
  constraint coordinate_pair check ((lat_user is null) = (lon_user is null)),
  constraint valid_lat check (lat_user is null or lat_user between -90 and 90),
  constraint valid_lon check (lon_user is null or lon_user between -180 and 180),
  constraint valid_name check (name is null or length(name) <= 60),
  constraint valid_crop_notes check (
    (recent_crop_note is null or length(recent_crop_note) <= 80)
    and (earlier_crop_note is null or length(earlier_crop_note) <= 80)
  )
);

create index parcels_owner_id_idx on public.parcels (owner_id);
alter table public.parcels enable row level security;

revoke all on public.parcels from anon, authenticated;
grant select, insert, update, delete on public.parcels to authenticated;

create policy parcels_select_own on public.parcels
  for select to authenticated using ((select auth.uid()) = owner_id);
create policy parcels_insert_own on public.parcels
  for insert to authenticated with check ((select auth.uid()) = owner_id);
create policy parcels_update_own on public.parcels
  for update to authenticated
  using ((select auth.uid()) = owner_id)
  with check ((select auth.uid()) = owner_id);
create policy parcels_delete_own on public.parcels
  for delete to authenticated using ((select auth.uid()) = owner_id);
```

**Security notes:** server must derive `owner_id` from verified identity, never accept it from the browser. `GRANT` + RLS are both needed. Coordinate columns are inherently sensitive, particularly with user-entered plot information; do not expose in publicly shareable representations. Use `updated_at` from a reviewed server-owned trigger or explicit server update, not a client-supplied timestamp; add trigger **only if requested/approved**, test it. `numeric(12,4)` and `decimal(9,6)` impose precision decisions; approve them before use. This schema is **not** a model-feature schema, and `zone_ui`/`irrigation_ui` intentionally do not claim crop science normalization. For a live service, add bounded request-body size, column grants as needed and backups.

## 6. SQL authorization tests and migration acceptance

**Use Supabase's local pgTAP test harness** and create two real authenticated test identities through supported helper functions or the project's verified fixture mechanism. Do not fake JWTs in client code. Test:

1. anonymous `SELECT/INSERT/UPDATE/DELETE` denied; `auth.uid()` null cannot access any private parcel.
2. user A creates A's parcel, can read/update/delete only their own.
3. user B cannot read/update/delete A's record, **even by guessing UUID**; client-supplied `owner_id = A` from B rejected.
4. area 0/negative and incomplete/out-of-range coordinate pair rejected; optional unknown values accepted only as specified.
5. deletion of user (after approved lifecycle review) does not leave orphaned parcel records; no public views bypass RLS.

## 9. Troubleshooting / stop conditions

- **No real Supabase project / phone provider:** setup and schema work may proceed locally after C01/C03; *real auth/public posts stay unavailable*.
- **CI/Next version mismatch:** inspect `package.json`, `.nvmrc`, existing `src/app/api`; update **this guide's full blocks** to match actual app before pasting.
- **RLS unauthorized request passes:** block merge; fix grants/policies, run both JWT and public/anon tests again.
- **`supabase db reset` points to wrong DB:** stop; confirm target before destructive action.
- **Model service not ready:** unrelated to B1. Do not add model results or score assumptions to foundation.

**Definition of done:** C01/C03 approved, schema migrations and environment documented, security tested, complete tested SQL committed to the updated guide, all frontend gates green, non-secret deploy config, verified local merge and remote SHA. Otherwise mark B1 `BLOCKED/NOT VERIFIED`.
